## The 90-second version

Most AI-built app rejections come from six places. Fix these before you submit and you will beat most people who buy this:

1. **Native capability (Apple 4.2 / Google "limited functionality").** A WebView pointing at a URL is a web clip. You need push notifications, offline mode, biometric unlock, share extension or a widget — used in the real flow, not bolted on decoratively.
2. **Demo account (Apple 2.1 / Google test instructions).** If your app has a login and the reviewer cannot get in, you lose 3–7 days. Pre-fill the demo account with data. Attach a screen recording.
3. **Account deletion (Apple 5.1.2 / Google User Data).** Mandatory if you allow sign-up. In-app button AND a web URL that works without the app. Deactivation is not deletion.
4. **Privacy manifest + encryption declaration (ITMS-91053).** `PrivacyInfo.xcprivacy` and `ITSAppUsesNonExemptEncryption`. Neither is ever generated by an AI tool. Both block submission entirely.
5. **Payments (Apple 3.1.1).** Digital goods on iOS must use StoreKit. A Stripe checkout inside the iOS binary is an automatic rejection.
6. **Google Data safety form.** Declare Device IDs if you use Firebase, OneSignal, Sentry, GA4 or Crashlytics. Almost everyone forgets. Mismatch with the form is a rejection.

And the calendar one that is not a code problem at all:

7. **Google Play 12 testers / 14 days.** Personal accounts created after 13 Nov 2023 must run closed testing with 12 opted-in testers for 14 consecutive days before production. Start recruiting on day one of development, not the day you finish.
